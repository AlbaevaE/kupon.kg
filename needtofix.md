# Аудит безопасности и архитектуры kupon.kg

## 🔴 Критические дыры в безопасности

**1. Произвольная загрузка файлов → XSS / Path Traversal**
`app/api/business/settings/route.ts` — загрузка логотипа без проверки типа, без проверки расширения, без лимита размера. Файл сохраняется в `/public/logos/` под именем `{businessId}.{ext}`, а `ext` берётся тупо через `logo.name.split(".").pop()`. Атакующий загружает `evil.html` или `evil.svg` с JS-пейлоадом — и он уже хостится на вашем домене. Это stored XSS с нулевыми усилиями.

**2. `NEXTAUTH_SECRET` — буквально "change-me-in-production"**
`.env` строка 4. Если это когда-нибудь уедет в прод как есть — любой человек, прочитавший этот комментарий в README любого проекта, сможет подделать JWT-токены и зайти под любым аккаунтом.

**3. Race condition при погашении купона**
`app/api/coupons/[code]/redeem/route.ts` строки 26-45 — читает статус, потом пишет в `$transaction`. Два параллельных запроса оба прочитают `status: "ACTIVE"` до того, как один из них запишет `"REDEEMED"`. Один купон погашается дважды. Правильно: `updateMany({ where: { id, status: 'ACTIVE' } })` и проверить `count`.

**4. Self-claim полностью сломан**
`app/claim/[templateId]/self-claim-form.tsx:24` вызывает `/api/templates/${templateId}/coupons`. Тот же endpoint, `app/api/templates/[id]/coupons/route.ts:9-10`, требует `session`. Неаутентифицированный пользователь всегда получает 401. Фича просто не работает.

**5. `maxUses` — мертвое поле**
Схема есть, UI показывает, но `app/api/templates/[id]/coupons/route.ts` никогда не проверяет сколько купонов уже сгенерировано. Можно генерировать бесконечно.

## 🟠 Архитектурные провалы

**6. `proxy.ts` — мертвый код**
Next.js middleware должен называться `middleware.ts`. Файл `proxy.ts` никогда не выполняется как middleware. Вся защита дэшборда на уровне middleware — иллюзия. Работает только потому что страницы дублируют проверку сами.

**7. `Business.passwordHash` — мусор в схеме**
У `Business` есть `passwordHash`, но аутентификация идет только через `StaffMember`. При регистрации один и тот же пароль хешируется дважды и хранится в двух местах. Поле `Business.passwordHash` не используется нигде.

**8. Статус `EXPIRED` никогда не пишется в БД**
Нет ни крона, ни фонового джоба. Вычисляется на лету при каждом чтении. Запрос `coupon.findMany({ where: { status: 'EXPIRED' } })` вернет пустой массив. Любая аналитика по просроченным купонам — ложь.

**9. `(user as any)` — TypeScript как декорация**
Используется 15+ раз во всех API-роутах. Все авторизационные проверки (`user.businessId`, `user.role`) идут через `any`. Опечатка — молча `undefined`. TypeScript здесь ничего не гарантирует.

**10. Нет пагинации нигде**
`app/dashboard/templates/[id]/page.tsx` загружает все купоны шаблона: `coupons: { orderBy: ..., include: ... }` без `take`. 50 000 купонов у популярного шаблона — и страница упадет по памяти.

**11. QR-код генерируется на каждый рендер**
`app/c/[code]/page.tsx:15` вызывает `QRCode.toDataURL()` при каждом запросе страницы купона. Результат детерминирован — его надо кэшировать или считать один раз.

**12. Slug хранится, но не используется**
У `Business` есть уникальный `slug`, `uniqueSlug()` делает N последовательных запросов к БД чтобы его найти. Никакого роута `/{slug}/` не существует. Это N+1 запросов впустую при регистрации ради поля, которое нигде не применяется.

**13. `NEXT_PUBLIC_APP_URL` используется на сервере**
`app/api/coupons/[code]/qr/route.ts:20` использует `NEXT_PUBLIC_APP_URL` в серверном API-роуте. `NEXT_PUBLIC_` переменные запекаются в клиентский бандл при билде. Для серверного кода нужна обычная `APP_URL` без префикса.

## 🟡 Мелочи, которые складываются

- **Нет лимита на размер тела запроса** — любой `req.json()` без проверки. 1 ГБ JSON — DoS.
- **Нет валидации email-формата** при регистрации. `not-an-email` пройдет.
- **Нет минимальной длины пароля**. Пароль `"1"` принимается.
- **Отсутствует rate limiting** на `/auth/login`. Брутфорс — без ограничений.
- **`validate` endpoint пишет `VIEWED` scan-event при каждом вызове** — включая автоматические запросы, health checks, атакующих. Logs засорены мусором.
- **Серверные компоненты обращаются к Prisma напрямую** минуя API — нет единого контракта, нет возможности переиспользовать из мобильного приложения.

## Приоритеты

| # | Что | Почему срочно |
|---|-----|---------------|
| 1 | Валидация файлов при загрузке | XSS на вашем домене прямо сейчас |
| 2 | Переименовать `NEXTAUTH_SECRET` и поменять значение | JWT можно подделать |
| 3 | Atomic redeem (`updateMany` + count check) | Двойное погашение |
| 4 | Починить self-claim (убрать auth или сделать отдельный публичный endpoint) | Фича не работает |
| 5 | Проверка `maxUses` при генерации купона | Бизнес-логика нарушена |
| 6 | Переименовать `proxy.ts` → `middleware.ts` | Middleware — мертвый код |
